# HUME - Roadmap

## Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Language | **Rust** | Memory-safe, zero-cost abstractions, best TUI ecosystem (crossterm + ratatui). Expressive type system with pattern matching, algebraic types, and macros. Ideal learning project. |
| Text storage | **Rope** (via `ropey`) | Efficient for large files, O(log n) edits anywhere, built-in line indexing. Used by Helix. |
| Scripting / Config | **Steel** (Rust-native Scheme) | Lisp syntax, designed for embedding in Rust. Helix is adopting it. Used for both plugins and configuration. |
| Scripting crate boundary | **`EditorHost` trait inversion + `hume-scripting/` crate** | Severs editor-domain coupling from the Steel host via trait inversion. `hume-platform/` hosts terminal I/O and OS helpers. |
| Steel scripting layers | **BOOTSTRAP → prelude → `core:stdlib`** | Three surfaces by audience: BOOTSTRAP (embedded in `builtins/mod.rs`) holds core dispatch, available in every engine; `runtime/scheme/prelude.scm` holds convenience macros for init.scm; `core:stdlib` (explicit `load-plugin`, no auto-load) collects selection-query commands for plugin authors, called cross-plugin via `call!` (no `require`/`provide` — a plugin never imports another plugin's module). The `cursor-char-index` builtin was removed with this split (zero production callers); it has since returned as a `core:stdlib` command (`stdlib/cursor-char-index`) backed by `(current-selections)` — no separate host-trait method needed for it. |
| Selection read API | **`(current-selections)` → `(anchor head primary?)` triples; queried via `core:stdlib` commands** | Raw 0-indexed char offsets, inclusive selection model (anchor == head is a 1-char selection), direction preserved (anchor > head for backward selections, never normalized), sorted by selection start, exactly one `primary?` = `#t`. `#f` sentinel when the focused (pane, buffer) has no seeded pane state — mirrors `current-line-number`. Tuples are treated as opaque outside the builtin: `core:stdlib` exposes `call!`-able commands (`stdlib/all-single-char?`, `stdlib/single-selection?`, `stdlib/cursor-char-index`) so plugin code never hardcodes tuple field order; the per-triple accessors composing them are module-private (no `(provide)` — cross-plugin access is `call!`-only). A companion `(char-index->line idx)` builtin does the char→line conversion as a separate primitive rather than folding a line number into each tuple — line is derived data (needs rope access Steel doesn't have) and ambiguous for a multi-line selection, so it's opt-in per call rather than computed for every selection whether needed or not. Char indices are raw char offsets, not grapheme ordinals — grapheme-ordinal conversion would be O(buffer) per call with no index structure to back it, versus O(log n) char-index operations; grapheme safety for future writes is meant to come from `next-grapheme-boundary`/`prev-grapheme-boundary` builtins mirroring `hume-editing/src/grapheme.rs`, not from a second coordinate system. |
| Editing model crate | **`hume-editing/` crate** | Pure bottom layer (no engine dependency) for the foundational text data model. Named `hume-editing` to avoid shadowing Rust's built-in `core`. |
| Tree-sitter crate boundary | **`hume-treesitter/` crate**: language registry, grammar attachment, parse worker, injection resolution | These had zero real dependency on `Editor` — only two `impl Editor` glue blocks (hooks, lazy-plugin activation, message log) tied them in. Boundary: registry/parsing/injections move out; the Editor glue and the engine's render-facing half (`SyntaxLayers`, `TreeSitterHighlighter`, `LoadedGrammar`) stay put. Depends only on `hume-engine` + `hume-editing`, acyclic. |
| `editor/` module layout | **Submodule dirs for name-clusters** (`buffer/`, `search/`, `syntax/`, `minibuf/`) | Suffix-named flat files (`buffer_store.rs`, `search_ops.rs`, `minibuf_history.rs`, `syntax_glue.rs`, …) encoded grouping in names instead of directories, and `editor/ops.rs` (buffer lifecycle) collided with the crate-level `ops/` (pure commands). Grouped into per-domain dirs; theme loading extracted to `editor/theme.rs`. Existing dirs (`commands/`, `keymap/`, `mappings/`, `registry/`, `completion/`) and `lifecycle.rs` deliberately untouched. |
| LSP design | **See `LSP.md`** | All LSP decisions and shared reference live in `LSP.md` (the hub); per-task implementation cards live in `docs/lsp/step-{0..4}.md`. |
| toml crate version (P1, LSP hub) | **Stay on 0.8** — evaluated and rejected the 1.x bump | LSP's P1 fired the recorded upgrade trigger (serde entering the workspace). Attempted the mechanical bump: `toml::Value` moves behind a `serde` cargo feature in 1.x (mechanical, fine), but `toml::Value: FromStr` no longer parses a full multi-key document — only a single value expression — breaking `hume-engine`'s theme loader (`source.parse::<toml::Value>()` in `theme/loader.rs`) with 22 failing tests. This is real API churn, not a version bump; `toml` stays at 0.8 (`default-features = false, features = ["parse"]`) until the loader is rewritten against 1.x's document-parsing API (`toml::Table::from_str` / `toml_edit`), which is out of scope for LSP prerequisites. |
| Syntax highlighting | **Tree-sitter** | Incremental parsing, structural understanding. Enables text objects and structural navigation beyond just colors. Production-proven (Neovim, Helix, Zed, GitHub). |
| Key mapping | **Command-based** | Keys bind to named commands, not to other keys. No recursive/non-recursive distinction. Keymaps defined in Steel config. Supports nested keys for sequences/chords. |
| Editing model | **Select-then-act** | Motions create selections, actions operate on them. Multiple selections from day one (`Vec<Selection>`). Selections always inclusive — `anchor == head` is a 1-char selection, never a zero-width point. |
| Extend mode | **`e` toggle (primary) + Ctrl+motion (kitty bonus)** | Sticky mode; `e` mnemonic. Ctrl+motion rejected as universal modifier: fatal legacy-terminal collisions on 10 of 15 motion keys (`Ctrl+h`=Backspace, `Ctrl+[`=ESC, etc.). Alt rejected — types accented chars on macOS, physical layout issues on Windows. Kitty Ctrl+motion is a graceful bonus; explicit `Ctrl+letter` leaves use a `force_extend` flag instead. |
| Line selection | **`x`/`X` (walk down/up lines)** | `x` selects current line including `\n`; repeated `x` walks to next. `Ctrl+x`/`Ctrl+X` accumulate lines (force_extend, works in both kitty and legacy). `o` in extend mode flips anchor/head. Extend is bidirectional — see next row. |
| Extend direction (`w`/`b`, `x`/`X`) | **Bidirectional: anchor-unit for words, anchor-line span for lines** | Opposite-direction presses shrink the selection back instead of only ever growing (Helix/Kakoune's extend only grows). Words: the anchor's word is re-derived fresh from its current position on every press and always kept whole — crossing it flips the selection's direction rather than truncating the word. Lines: an unaligned selection is first aligned to full lines (direction fixed by which key was pressed), then each press moves the *head*'s line by ±1 relative to the anchor's line; clamps at the buffer's first/last line are head-relative, not selection-end-relative. |
| Delete char at cursor | **`d` (no separate binding)** | In select-then-act with always-inclusive 1-char selections, `d` on a fresh cursor deletes the char under it — identical to Vim's `x`. |
| Terminal I/O | **crossterm** | Cross-platform. Handles raw mode, key events, escape sequences. |
| Rendering | **ratatui as diffing engine** | Cell-level rendering via ratatui's double-buffer diffing. No widgets. Immediate-mode thinking with retained-mode optimization. |
| Terminal protocol | **Prefer kitty keyboard, fall back** | Probe at startup via direct TTY read. Use when available for unambiguous key encoding and modifier reporting. Fall back to legacy encoding otherwise. |
| Documentation | **Markdown + auto-generated command reference** | Hand-written Markdown guides for concepts. Command reference auto-generated from Rust doc comments. In-editor `:help` renders Markdown in a read-only buffer. |
| Plugin trust model | **Full trust, Helix-aligned; hardened Steel builtins + their sandbox removed** | `Engine::new()` already registered Steel's full stdlib (`steel/process`, `steel/filesystem`, `steel/ports`) globally in every plugin with no `require-builtin` — HUME's sandbox (path-prefix checks on `git-clone`/`curl-fetch`/`npm-install!`/`list-dir`/etc.) was never an enforcement boundary, only an unused "blessed path": plugins could always spawn arbitrary processes. Verified steel-core 0.8.2's own `Engine::new_sandboxed()` blocks fs/network/dylibs but *not* `steel/process` — real enforcement would mean shadow-registering empty same-name modules over `steel/process`/`steel/filesystem`/`steel/tcp`/`steel/http` + `disallow_dylib_loading()`, re-audited every steel-core upgrade, and diverging from the Helix plugin ecosystem (Helix's own maintainers: "right now there are no restrictions what a VM can do"). PLUM (`runtime/plugins/core/plum/*.scm`) rewritten against Steel's own `command`/`spawn-process`/`which`/`steel/filesystem` instead of the removed builtins. A small set of sandbox-free *utility* builtins survive where a Scheme rewrite would only make platform-conditional logic worse: `hume-target`/`data-dir`/`runtime-dir`/`path-join` (editor-integration info + Windows UNC stripping), `unpack-gz`/`unpack-zip` (chmod + archive-format selection), `sha256-file` (per-platform hashing tool selection), `compile-grammar!` (Windows C-compiler probing), `acquire-install-lock!`/`release-install-lock!` (O_EXCL install lock), and a new `run-inline-output!` (process-group-isolated spawn — Steel's `spawn-process` has no `setpgid`/`pre_exec`, needed because `#:inline-output` commands run with terminal raw mode off, so an unisolated child would be killed by the same Ctrl+C meant to interrupt only it). Full rationale, survivor list, and the real Steel-VM continuation-corruption bug found and fixed along the way (re-raising a native-builtin error out of a nested `with-handler` — see `feedback_steel_reraise_continuation_corruption` memory) are in the implementation history; nothing else documents this at doc-length. Decided and implemented 2026-07-13. |
| Theming | **Hierarchical scopes** | Dot-notation scopes (`keyword.function`, `ui.cursor`) with automatic fallback. Helix scope names for theme compatibility. Helix TOML theme format including `inherits` chains and `palette`. |
| Package manager | **PLUM (PLUgin Manager) — Steel script, swappable** | Core plugin (`core:plum`). Two namespaces: `core:name` (bundled) and `username/repo` (Git-based, no registry). Every plugin must appear in `init.scm` via `(load-plugin …)` or `(declare-plugin …)`. Disabling PLUM just removes management commands. |
| Lazy plugin loading | **Plugin manifests; load-once (no unload)** | `(load-plugin name)` = eager; `(declare-plugin name …)` = lazy manifest declaring `#:commands` / `#:events` / `#:languages` activation entries. Fail-fast on first error; no retry until `:reload-config`. No unload. |
| Plugin configuration | **`#:config` keyword; `(plugin-config)` read-back** | Both `load-plugin` and `declare-plugin` accept `#:config` (an opaque value, typically a hash), stored per-plugin at declare/load time. The plugin body reads it back via `(plugin-config)`, resolved from the top of the plugin attribution stack — identical for eager and lazy bodies since both push there for the duration of the eval. `core:vim-keybind` uses this for a `change-to-eol` (`'on`/`'smart`/`'off`) switch controlling its one default-shadowing binding (`C`). |
| Plugin namespace isolation | **One Steel module per plugin (`require`)** | Each plugin loads via `(require "<abs-path>")` giving its own module namespace. Cross-plugin calls go through `call!` only. |
| Plugin attribution / lifecycle | **Keep attribution, drop ledger; fail-fast** | `PluginId` / `Owner` / `PluginStack` / `cmd_owners` track who registered what. Mutation ledger and per-plugin rollback removed — Neovim/Helix ship no clean per-plugin unload. `:reload-config` rebuilds from scratch. |
| Command dispatch args | **Variadic `call!`; no side channel** | `(call! name args…)` dispatches to Steel or native commands. Arity-based injection: 0 params → nothing, 1 → count, 2/variadic → count+extend. |
| Indent queries | **Helix format (`indent.scm`)** | Reuse Helix per-language indent queries directly. Avoids reinventing a query format; gives a large library of languages for free. |
| Syntax highlight query granularity | **Per-line queries from tree root** | Each visible line runs the highlight query clipped via `set_byte_range` — cost is O(tree depth + line content), and span lookup stays a pure function of `(tree, rope, line)`: callable from anywhere in any order (render loop, future minimap/export, tests). Viewport-level batching rejected even behind a signature-preserving facade: it introduces a fill-before-read protocol (temporal coupling) that every future caller inherits, and the swap is localized behind one function so deferring has no compounding retrofit cost — it costs the same ~150 lines whenever done. Perf win invisible at current scale. Revisit bar: profiling shows query cost in the frame budget (e.g. under smooth scrolling). Revisit shape, in order: (1) one query per viewport with *pre-bucketing* — clip each capture into a per-line bucket at collection time (captures are tree-shaped and cross lines, so a naive group-by doesn't work; buckets avoid cross-line sweep state), refill every frame, guard out-of-range lookups; (2) only if that's not enough, a tree-version-keyed span cache for unchanged-buffer frames. |
| Unicode handling | **Grapheme clusters from day one** | All motions and selections use `unicode-segmentation`, not bytes or chars. Retrofitting is expensive. |
| Keymap defaults vs config | **Hardcoded defaults, config overrides** | Defaults in Rust as SSOT. User config (Steel) provides overrides only. Editor always works with zero config; missing or unparseable config silently uses defaults. |
| Jump-list eligibility | **Flag on `MappableCommand`** | `jump: bool` field (like `repeatable`) lets every command — Rust or Steel — declare jump intent at registration. A `const` list can't capture plugin commands that move the cursor directly. |
| Register linewise flag | **Heuristic: detect at paste time** | Trailing `\n` signals linewise content. No explicit flag stored; natural upgrade path if heuristic proves insufficient. |
| Paste on selection (`p`/`P`) | **Replace selection, no swap** | `p`/`P` on cursor inserts normally; on a multi-char selection, replaces it. Displaced text not written back — kill ring gives access to previous content. |
| Register `'c'` (clipboard) | **Editor layer** | Requires OS clipboard integration; belongs in editor layer, not core. |
| Read-only registers (`.`, `%`, `#`) | **Editor layer** | Require editor-level state (mode tracking, open file list); not implementable in core. |
| Register naming | **Mnemonic letters, `0`–`9` named storage** | `k` = kill-ring head, `c` = clipboard, `b` = black hole, `s` = search, `q` = default macro. 10 named registers (`0`–`9`) for symmetric in-memory storage. Default register (`"`) is internal. Kill ring reached via `"k` or `[`/`]` cycling. |
| Macro model | **Register-based, Vim-style, with `Q`/`q` UX** | Macros stored in registers. `q` = default. `QQ` records into `q`; `qq` replays. `Q` for record (deliberate setup); `q` for replay (hot path). Multiple saved macros without the full `a`–`z` Vim namespace. |
| Register picker UI | **Editor layer** | Popup listing registers with descriptions and contents when register prefix pressed. Makes register names discoverable without memorisation. |
| Dot-repeat scope | **Selection recipe + action** | Replays: last selection-establishing command + extend steps + editing command + insert keystrokes. Plain navigation not recorded. Recipe discriminated by `Selection::is_collapsed()` after each Motion/Selection command. Steel commands opt in via `#:repeatable #t`. Mutually exclusive with `#:inline-output`. |
| Surround operations | **`ms` + smart `r` (select-then-act, no `md`/`mr`)** | `ms` + char selects surrounding delimiters as two cursor selections. Delete = `ms(` → `d`. Replace = `ms(` → `r[`. Smart `r` maps open→open, close→close; symmetric delimiters use selection index as tiebreaker. Rejected: Helix `md`/`mr` which bake selection+action together, violating select-then-act. |
| Word motions (`w`/`b`/`W`/`B`) | **Select whole word** | `w` selects the next word entirely; `b` selects the previous word entirely. `e`/`E` removed as redundant. Diverges from Helix where `w` extends to start of next word. |
| Multi-buffer scope (M7) | **List + switch only; no splits or tab UI** | Multiple open buffers, `:e`/`:bnext`/`:bprev`/`:bd`. Splits and tabline deferred — require a layout engine. |
| Disjoint-borrow refactor | **Logic in free functions over sub-struct borrows, not `&mut self` methods on outer `Editor`** | `Editor` is a thin wrapper over three sibling sub-structs — `scripting`, `state` (`EditorState`, all command-mutable data), and `view` (`EngineView`). The split exists so command/editing logic can take the narrowest borrow (`&mut EditorState`, `&EngineView`, or individual fields) as a free function, letting Rust prove borrows disjoint instead of forcing workaround clones. A `&mut self` method on the *outer* `Editor` borrows all three at once, blocking that — such methods are reserved for lifecycle entry points, cross-cutting orchestration, and thin delegators. Enforcement is structural: the borrow checker rejects cross-sub-struct access from a sub-borrow, so a new whole-`Editor` borrow appears as an explicit clone or a new outer `&mut self` method in review — no separate lint. |
| Kitty push order on init | **Push after entering alt screen** | Some terminals maintain a per-screen keyboard stack. Pushing before `EnterAlternateScreen` lands flags on the primary screen's stack, which key reads don't consult. |
| SHIFT normalization | **Strip bare SHIFT for any Char** | Terminals that don't honour `REPORT_ALTERNATE_KEYS` send shifted punctuation as `Char + SHIFT`, missing trie bindings. Strip SHIFT for any `Char` when SHIFT is the only modifier (`Ctrl+Shift` keeps CONTROL; `Shift+Tab` = `BackTab` is not a `Char`). |
| Kill-ring whitespace collapse | **Overwrite pure-whitespace head in place** | On push, if the ring head is pure-whitespace, the new entry overwrites it instead of taking a fresh slot. Keeps swap-junk from filling the ring; the whitespace stays retrievable until the next push. |
| Tab handling | **One knob (`tab-style`), reuse `tab-width`** | Tab key inserts `\t` (hard) or spaces to next tab stop (soft). `tab-width` reused for both rendering and Tab-key spacing. Vim's four-knob `shiftwidth`/`softtabstop` model rejected as too complex. Enter copies leading whitespace verbatim. |
| Diff module | **histogram + Myers fallback, `similar` hidden** | `diff_lines`: histogram with wall-clock deadline, falls back to Myers on timeout. `diff_words`: Myers over UAX #29 word-boundary tokens with deadline. `similar` is a hidden impl detail — public types owned by `hume-editing` so consumers never depend on the backend. |
| `:split` / `:vsplit` direction mapping | **`:split` = top/bottom stack → engine `Direction::Vertical`; `:vsplit` = side-by-side → `Direction::Horizontal`** | Vim convention. Engine `Direction` partitions the named axis, so the enum name is the inverse of intuition — a named constructor/helper prevents bugs. |
| Split buffer | **Duplicate focused pane's buffer** | `:split`/`:vsplit` mirror the focused pane's buffer; optional `<path>` arg opens a different buffer. Matches Helix multi-pane contract. |
| Jump list on split | **Same-buffer split clones source; diverges thereafter** | A same-buffer `:split`/`:vsplit` clones the source pane's `JumpList` (entries + cursor) so the new pane can Ctrl+O back to pre-split positions. Different-buffer split starts empty. After the split each pane's jumps mutate independently. |
| Close-pane | **`Ctrl+p c` / pane-aware `:q`; no `:close`** | Prunes the focused leaf, collapses the parent `Split`, refocuses the sibling. `:q` closes the focused pane when others are open; only falls through to its existing buffer/quit logic on the sole pane. `Ctrl+p c` on the sole pane warns instead of quitting — `:q` alone owns quitting. |
| `wrap_mode` scope | **Moved onto `Pane`; `EditorSettings.wrap_mode` is init-default only** | Wrap is a view property, not a document preference. `BufferOverrides.wrap_mode` removed. Runtime per-pane override added via `:set pane wrap-mode=<value>` (2026-07-03) — `Pane` also carries `saved_wrap_mode` (always a wrapping variant) so `:wrap` toggle-on restores whatever mode the pane last wrapped with instead of hardcoding `indent`. Steel-side per-pane/per-buffer `set-option!` still deferred — only `Global` scope is scriptable. |
| Dynamic decoration content (engine) | **Per-frame text arena for cells; `Cow` for gutter; `Box<str>` for whitespace glyphs** | `CellContent::{Virtual,Indicator}` hold `{start: u32, len: u16}` ranges into `FormatScratch::virtual_texts` (cleared per buffer line/virtual row) instead of `&'static str`, so `Grapheme` stays `Copy` while decoration text (LSP hints, Steel icons) can be computed at runtime. `InlineInsert.text` and `VirtualLine::{text, segments}` are owned (`String`); the pipeline builds virtual-line graphemes itself from `text`+scoped byte-range `segments` rather than trusting provider-built `Grapheme`s. `GutterCellContent::Text(Cow<'static, str>)` replaces `Static`/`Number`. `WhitespaceConfig`'s three glyph fields are `Box<str>`. |
| Sign column tie-breaking (`SignColumn`) | **Higher `priority` wins; ties go to the later-registered source** | `SignColumn` merges `Sign`s from multiple `SignSource`s (diagnostics, git, breakpoints, bookmarks) into one narrow gutter column via `max_by_key(priority)`, which keeps the *last* max on ties — i.e. registration order breaks ties, not first-registered-wins. `GutterCell.scope` gained a `GutterScope::{Name(Scope), Id(ScopeId)}` split so `Sign` (and any future fast-path gutter provider) can carry an already-interned `ScopeId` like `HighlightSource`/`InlineInsert` do, instead of forcing every gutter column through the by-name resolve path. |
| Virtual-line-aware scroll/cursor math (U8, `docs/lsp/step-3.md`) | **Landed end to end; wrap-mode paths only** | U8a: `hume-editor`'s `cursor::screen_pos`/`screen_to_char_offset` and `scroll::ensure_cursor_visible`/`scroll_cursor_to_row`/`scroll_backward_from_cursor` thread `&ProviderSet`/`content_width` through and use `format::display_rows_for_line`'s `RowsBreakdown` (`{before, content, after}`) instead of content-only `count_visual_rows`. Scoped to the *wrapping* code path only: `ensure_cursor_visible_unwrapped` (no-wrap vertical scroll) and `ensure_cursor_visible_horizontal`/`format_row_col` (column math, never cross-line) stay untouched — a virtual line's effect on no-wrap vertical scrolling remains unhandled. A viewport's own top line never shows its own `before` block (shown only when reached mid-walk from an earlier top line) — landing `top_row_offset` exactly at a line's content-row-0 must round the cut *down* past any `before`, never overshoot into it, since virtual rows can't be partially scrolled; this was a real bug caught by the U8a synthetic-provider tests, not a design choice made in advance. U8b: the first real `VirtualLineSource` (`PaneVirtualLines`, per-pane `HashMap<line, Vec<VirtualLine>>`) is fed by `update_virtual_line_providers` from `decorations.virtual_lines`, gated on a `virtual_lines_generation` counter (bumped by `set_virtual_lines`) so the per-pane mirror only rebuilds on a real change, not every frame — this runs in scroll/cursor math too, not just render. `VirtualLineEntry` gained an optional whole-line `scope` (`(line text)` or `(line text scope)`), falling back to the `ui.virtual` theme key (the same one `Theme::ui.virtual_text`, the struct field, resolves from) when absent. Every entry anchors `After(line)` — no `Before` in v1. `ViewportState.top_row_offset` keeps indexing content (wrap) rows only, unchanged from the row above. |
| Startup ordering (b/w→highlighted flash) | **Scripting init runs before terminal init; `draw_once` removed** | `init_scripting` (Steel VM boot + `init.scm`, ~150-200 ms) now runs while the terminal is still in normal/cooked mode — the shell stays visible instead of an unthemed alt-screen frame, and the alt-screen only opens once the editor is fully themed. The kitty keyboard probe is split out of `terminal::init` into a new `terminal::probe_kitty()` (runs on the normal screen, raw-mode-only) so `set_kitty_support` can still install kitty-only default keybinds *before* `init.scm` evaluates user `bind-key!` calls — this ordering is load-bearing (`apply_kitty_defaults` does plain overwriting `bind_leaf` calls). An early tree-sitter-parse-kickoff variant (detecting/posting the initial buffer's parse before `init.scm`, to shave one further imperceptible frame) was considered and **rejected**: it required a compensating re-activation pass for lazy `#:languages` plugins (the early call runs while `scripting == None`, silently skipping `activate_lazy_language_plugins`, and the existing end-of-init detect loop would then no-op on the unchanged-language guard) — not worth the non-linear code path for one ~10 ms frame. `init_scripting`'s internals are unchanged; the existing end-of-init `detect_and_set_language` loop still posts the initial parse. Steel/`im-rc`/`lasso` crates pinned to `opt-level = 3` in the dev profile (Engine::new: ~120 ms → ~107 ms). Accepted trade-offs: keys typed during the pre-alt-screen window echo to the shell instead of reaching the editor; `init.scm`'s `(set-option! 'mouse-enabled …)` now takes effect at startup (previously ignored until an inline-output round-trip). |
| Tree-sitter injections (M11) | **Engine-owned `SyntaxLayers`; worker-resolved; depth cap 3; root incremental, layers always full-parse** | `SharedBuffer.tree: Option<Tree>` became `SharedBuffer.syntax: Option<SyntaxLayers>` (`hume-engine/src/syntax_layers.rs`) — root tree + injected layers live together engine-side since both halves (`Tree`, `TreeSitterHighlighter`) are already engine types; the `get_syntax` render closure was deleted. `GrammarBundle` gained a shared `Arc<TreeSitterHighlighter>` (built once at `attach_grammar`, not per buffer) and an optional compiled `injections.scm` (`InjectionsQuery`); a broken `injections.scm` hard-fails the attach, same as a broken `highlights.scm` — both come from the same trusted pinned source, so no separate soft-degrade path was added. Resolution (`hume-editor/src/editor/injections.rs`) runs on the parse worker after the root parse: matches `@injection.content`/`@injection.language` captures, static `#set! injection.language` wins over a dynamic capture, `#set! injection.combined` merges all matches of one pattern+language into a single layer (required by `markdown.inline`), `#set! injection.include-unnamed-children` controls whether a content node's *unnamed* (anonymous/punctuation) child ranges are excluded (default) or included — named children are never excluded regardless, since they're meaningful grammar constructs, not delimiters. Unknown/grammarless injection languages are skipped silently — no lazy install. Recursion caps at depth 3 (`MAX_INJECTION_DEPTH`) — covers markdown→rust→rustdoc-comment→markdown. Injected layers are always full-parsed (never incremental) since per-layer identity tracking across edits isn't worth it for typically-small regions; the root parse stays incremental as before. `bake_pending_edits` applies every `InputEdit` to every layer's tree (coordinates are absolute buffer bytes) and refreshes each injected layer's cached `ranges` from `tree.included_ranges()` afterward. Highlight priority across overlapping layers is **depth-first**: `flatten_overlaps` sorts its active-interval stack by `(depth, seq)` so a nested injection's captures always win over its parent's regardless of collection order — a real ordering bug (deeper layers collected earlier in a flat push would otherwise lose) was caught and fixed by a dedicated test before ship. Two more correctness gaps surfaced only by live end-to-end verification (manually running `:plum-install-grammar` in a real terminal) rather than by unit tests, since the test suite initially validated against the *grammar's own bundled* `injections.scm`/`highlights.scm` rather than the *Helix-maintained* ones PLUM actually installs — the two disagree on both the injected language name (`markdown.inline`, not the bundled file's `markdown_inline`) and the children-inclusion property name (`injection.include-unnamed-children`, not `injection.include-children`). Fixed by recognizing the real property name and copying Helix's `injections.scm` into the test fixtures (`scripts/fetch-test-grammars.sh` fetches it from the pinned commit) so `markdown_buffer_installs_root_plus_injected_layers` exercises what PLUM really ships. PLUM (`runtime/plugins/core/plum/grammars.scm`) fetches `injections.scm` best-effort (`with-handler` around `plum/try-fetch-injections!`, since a 404 must not abort the whole grammar install — post-2026-07-13 full-trust migration, the fetch itself runs via `run-inline-output!` and is deliberately *not* wrapped in its own inner handler, to avoid a Steel VM continuation-corruption bug found in that migration; see the "Plugin trust model" decision above) and installs declared dependency grammars first (`*plum-grammar-deps*`, markdown → `markdown.inline`, same name Helix's injections.scm resolves `(inline)` to — no renaming needed) so a fresh `:plum-install-grammar markdown` pulls in the inline grammar transparently. |
| Highlight provider data scope | **Per-pane (`PaneHighlights`), never global** | `bracket_hl_data`/`search_hl_data` were global `Arc<RwLock<...>>`s shared by every pane's `SharedHighlighter`, but computed only from the *focused* buffer/viewport — a pane viewing a different buffer, or the same buffer scrolled elsewhere, rendered the focused pane's highlight bytes onto its own text. Fixed by giving each pane its own `bracket`/`search` Arcs (`PaneHighlights`, allocated in `build_pane`, stored in `EditorState.panes.highlights`); `update_highlight_providers` now computes each pane's search highlights from that pane's own buffer/viewport, refreshing the match cache regardless of focus. Bracket-match highlighting stays focused-pane-only (a cursor concept), clearing every pane's bracket Arc each frame so a stale match doesn't linger after focus moves away. Folded in the same pass: a search match spanning `\n` now emits one highlight span per touched line (`push_match_highlight_lines`), clipped to each line's own content — the prior single-span conversion could resolve a byte offset through the wrong line whenever a match crossed a line boundary. |
| Vim-only keys (`0`/`^`/`$`/`Ctrl+6`) | **Moved to opt-in `core:vim-keybind` plugin; `C`/`D`/`G` added there** | These four duplicated existing native gotos (`g h`/`g s`/`g l`) or vim's `Ctrl+^` — removed from `hume-editor/src/editor/keymap/defaults.rs`, restored only by `(load-plugin "core:vim-keybind")`. The plugin also adds `C`, `D` (delete-to-EOL, free of defaults), and `G` (`goto-last-line`, also free). `C` is conditional on selection width (checked via `(call! "stdlib/all-single-char?" …)`, requiring `core:stdlib` loaded first): on a bare cursor it's change-to-EOL; with a real (multi-char) selection it falls back to shadowing the default `copy-selection-on-next-line` instead, so HUME's multicursor idiom stays reachable without dropping vim muscle memory for the common case. `C`/`D` are plain `define-command!` composites (`(call! "goto-line-end" 1 #t)` then `change`/`delete`) with no `#:repeatable` flag — confirmed by a flip test that native `delete`/`change` are themselves repeatable and self-capture the preceding extend step via the shared selection-recipe accumulator, so the wrapper needs no cooperation from dot-repeat. Other vim-inherited defaults (`{`/`}`, `Ctrl+o`/`Ctrl+i`, `Ctrl+d`/`Ctrl+u`, `z z`/`z t`/`z b`) were deliberately left in place — they have no native duplicate and moving them would make those features key-unreachable by default. |
| `j`/`k` count semantics | **No count → visual (display) line; explicit count → buffer line; a bare keypress or a Steel-side count of `0` are both "no count"** | Matches relative-line-number gutter conventions (`9j` jumps 9 logical lines, not 9 wrapped display rows). `apply_visual_vertical` (`hume-editor/src/editor/visual_move.rs`) takes an explicit `by_buffer_line: bool` param rather than reading `EditorState.explicit_count` itself, so it stays a pure function of its arguments: the `move-down`/`move-up` commands pass `state.explicit_count`, while page/half-page scroll and mouse-wheel scroll always pass `false` — a scroll count is inherently a display-row measure, never a buffer-line one, regardless of whether the user typed a count. Count travels as `Option<usize>` through `CmdCtx`/`execute_keymap_command` — `None` means "as if no count was typed" and is producible by the keymap trie leaves and the WaitChar arm (`hume-editor/src/editor/mappings/normal.rs`) for a bare keypress, and by Steel: `parse_count_extend` (`hume-scripting/src/builtins/commands.rs`) decodes a script-side count of `0` to `None`, since Scheme has no `Option` to pass across the builtin-call boundary and `0` is otherwise unreachable as an explicit count. A no-arg `call!`/typed `:move-down` still defaults to `Some(1)` (buffer line) — visual-row movement from Steel is opt-in, never implicit. `run_steel_command` (`hume-editor/src/editor/mod.rs`) injects `ctx.count.unwrap_or(0)` into a counted lambda's `count` param, so a wrapper that forwards `count` straight into `(call! "move-down" count extend)` round-trips a bare keypress back to visual-row movement — the `move-down-select-word` pattern in `runtime/init.scm.example`. The bare-name Steel wrappers generated by `register_command_names` (`hume-scripting/src/lib.rs`) are variadic (`(lambda args (%dispatch-command "name" args))`) so `(move-down 0)` works without going through `call!`. `run_native_body` (`hume-editor/src/editor/commands/mod.rs`) is the single writer of `state.explicit_count` — it save/sets/restores around the command body, so a Steel command's own nested `call!` gets its own value instead of inheriting whatever the outer keystroke set. Softened trade-off: `(call! "repeat-last-action" 0)` from Steel now replays the *original* action's count (same as keyboard bare `.`) rather than always count 1, since `cmd_repeat` reads `explicit_count` the same way `move-down`/`move-up` do. |
| `*` semantics | **Vim-style word-under-cursor (`search-word-under-cursor`), diverging from Helix** | `*` always expands to the word under the head regardless of any existing selection, matching Vim rather than Helix's "search the selection" behaviour — the same divergence category as the word-motions row above. Helix's behaviour is still reachable, just moved to its own binding: `Ctrl+/` (`search-selection`) searches the primary selection's literal text with no expansion or whole-word anchors. |
| `Ctrl+/` binding | **Kitty-only, no legacy-terminal alias** | Legacy terminals encode `Ctrl+/` as `0x1F`, which crossterm decodes as `Ctrl+'7'` — colliding with a plausible future binding on that key. Rather than accept the collision risk, `search-selection` is left unbound (silently a no-op) on non-kitty terminals; kitty-protocol terminals get the real `Ctrl+/` keycode with no ambiguity. |
| `whitespace-newline` values | **Narrowed to `none`/`all`; `trailing` removed** | A newline is inherently always at end-of-line, so the `trailing` axis meaningful for `whitespace-space`/`whitespace-tab` (content vs. trailing whitespace) never distinguished anything for `whitespace-newline` — it was a dead third option. `parse_show_newline` now returns a plain `bool` instead of routing through `WhitespaceRender`. Breaking for any pre-existing config setting it explicitly to `trailing`, accepted pre-release with no migration path. |

## Open Questions

| Question | Context |
|----------|---------|
| Multiline quote text objects | Quote text objects (`i"`, `i'`, `` i` ``) are line-bounded because the parity scan gives wrong results when earlier lines contain unmatched quotes. Brackets don't have this problem (asymmetric delimiters allow depth tracking). Tree-sitter can resolve the ambiguity — use syntax-aware matching when a grammar is loaded, fall back to line-bounded parity otherwise. |
| Register paste count mismatch | When yank uses N cursors but paste uses M≠N, Helix falls back to pasting the full register at every cursor. Explore alternatives with real usage data (e.g. cycling slots, clamping to last slot, user-facing warning). Decide after more real usage. |
| Common-prefix auto-extend on Tab | Readline/bash behaviour: on Tab with ≥2 candidates, first extend the input to their shared prefix before opening the popup. Current behaviour skips straight to cycling. Small UX polish; decide after more real usage whether the extra keystroke saved is worth the surprise of input mutating mid-type. |
| Plugin-defined languages × lazy loading | Language identity/detection is HUME-owned (`runtime/scheme/languages.scm`, eager). A plugin keying `#:languages` off an *existing* language works fine. But a plugin that defines its **own** language must register that identity **eagerly** — a lazy body cannot be the sole provider of its own activation language (chicken-and-egg). Deferred to a dedicated brainstorm. |
| `llvm-mir` / `llvm-mir-yaml` grammar mismatch | Inherited from Helix: `llvm-mir-yaml` defines the `.mir` extension but delegates to the `llvm-mir` grammar (no separate compiled grammar). `llvm-mir` itself has no extension binding. Track upstream; no HUME-specific fix needed until then. |
| Undercurl blocked on ratatui underline-shape support | `UnderlineStyle::{Wavy,Dotted,Dashed}` all collapse to plain `Modifier::UNDERLINED` in `From<ResolvedStyle> for ratatui::style::Style` (`types.rs`) — ratatui's `Modifier` bitflags have no underline-shape bits and its crossterm backend never emits `Undercurled`/`Underdotted`/`Underdashed`, though crossterm itself supports them. No clean injection point between the engine and the terminal today. Deferred: the engine model and theme loader are already correct, so this needs no engine change once ratatui adds underline-shape support — revisit then. |
| `ProviderSet::remove` unwired | Engine primitive `ProviderSet::remove` (`hume-engine/src/providers.rs`) is implemented and tested but has no editor call site — provider ids returned by `build_pane`'s `add_*` calls are discarded, and nothing dynamically registers/deregisters a provider. Wire it when the first real consumer lands: (a) Steel provider-registration builtins (plugin-added columns/overlays), or (b) a gutter-visibility `:set` toggle that removes/re-adds a built-in column. Until then, capturing ids on the pane would be speculative. |
| Search-state clobbering from Steel | Exposing search commands (`search-next`, `select-all-matches`) to Steel lets a plugin's own pattern overwrite the *user's* interactive search state (last pattern, direction) — after the plugin runs, pressing `n` jumps to the plugin's pattern instead of the user's. Decide before exposing: pattern-taking variants that don't touch shared state, or documented clobbering. |
| Mark/bookmark drift across edits | A char offset returned by `(current-selections)` and stored by a plugin (bookmark, saved position) goes stale as edits land before it's used — the index is still a valid grapheme boundary, just pointing at the wrong place. Real marks need positions mapped through `ChangeSet`s as edits happen; decide where that mapping lives and which stored positions opt in, or document verbatim store/restore as edits-must-not-intervene. |
| Snap-vs-error policy for future selection setters | A future `set-selections!`/`goto-char!`-style builtin must handle out-of-range or mid-cluster input from Steel (e.g. computed from string search offsets). Two options: snap to the nearest valid grapheme boundary (forgiving, but can silently hide a plugin bug), or raise (fail-fast, but breaks a legitimately-drifted stored position). Decide per call site before the first setter lands — no setter exists yet, so nothing is blocked on this today. |
