# HUME - Roadmap

## Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Language | **Rust** | Memory-safe, zero-cost abstractions, mature TUI ecosystem (termina + ratatui). Expressive type system with pattern matching, algebraic types, and macros. Ideal learning project. |
| Text storage | **Rope** (via `ropey`) | Efficient for large files, O(log n) edits anywhere, built-in line indexing. Used by Helix. |
| Scripting / Config | **Steel** (Rust-native Scheme) | Lisp syntax, designed for embedding in Rust. Helix is adopting it. Used for both plugins and configuration. |
| Scripting crate boundary | **`EditorHost` trait inversion + `hume-scripting/` crate** | Severs editor-domain coupling from the Steel host via trait inversion. `hume-platform/` hosts terminal I/O and OS helpers. |
| Steel scripting layers | **BOOTSTRAP → prelude → `core:stdlib`** | Three surfaces by audience: BOOTSTRAP (`builtins/bootstrap.scm`, embedded via `include_str!` in `builtins/mod.rs`) holds core dispatch, available in every engine; `runtime/scheme/prelude.scm` holds convenience macros for init.scm; `core:stdlib` (explicit `load-plugin`, no auto-load) collects selection-query commands for plugin authors, called cross-plugin via `call!` (no `require`/`provide` — a plugin never imports another plugin's module). |
| Selection read API | **`(current-selections)` → `(anchor head primary?)` triples; queried via `core:stdlib` commands** | Raw 0-indexed char offsets, inclusive selection model (anchor == head is a 1-char selection), direction preserved (anchor > head for backward selections, never normalized), sorted by selection start, exactly one `primary?` = `#t`. `#f` sentinel when the focused (pane, buffer) has no seeded pane state — mirrors `current-line-number`. Tuples are treated as opaque outside the builtin: `core:stdlib` exposes `call!`-able commands (`stdlib/all-single-char?`, `stdlib/single-selection?`, `stdlib/cursor-char-index`) so plugin code never hardcodes tuple field order; the per-triple accessors composing them are module-private (no `(provide)` — cross-plugin access is `call!`-only). A companion `(char-index->line idx)` builtin does the char→line conversion as a separate primitive rather than folding a line number into each tuple — line is derived data (needs rope access Steel doesn't have) and ambiguous for a multi-line selection, so it's opt-in per call rather than computed for every selection whether needed or not. Char indices are raw char offsets, not grapheme ordinals — grapheme-ordinal conversion would be O(buffer) per call with no index structure to back it, versus O(log n) char-index operations; grapheme safety for future writes is meant to come from `next-grapheme-boundary`/`prev-grapheme-boundary` builtins mirroring `hume-editing/src/grapheme.rs`, not from a second coordinate system. |
| Editing model crate | **`hume-editing/` crate** | Pure bottom layer (no engine dependency) for the foundational text data model. Named `hume-editing` to avoid shadowing Rust's built-in `core`. |
| Tree-sitter crate boundary | **`hume-treesitter/` crate owns all tree-sitter machinery**: language registry, grammar attachment (`grammar.rs`), parse worker, injection resolution, and the render-facing half (`layers.rs`'s `SyntaxLayers`, `highlight.rs`'s `TreeSitterHighlighter`). `hume-engine` no longer links `tree-sitter`, `tree-sitter-language`, `libloading`, or `streaming-iterator` at all — it consumes only `(start, end, ScopeId)` highlight spans via the `SyntaxSpans` trait (defined in `hume-engine/src/providers.rs`, implemented by `hume-treesitter`'s `Syntax`), the same dependency shape as `StatuslineProvider`. | `hume-treesitter` depends only on `hume-engine` + `hume-editing`, acyclic; `Editor` has no tree-sitter dependency beyond hooks, lazy-plugin activation, and the message log. |
| Tree-sitter test seams | **`InlineParseBackend` cfg-gated behind `test-util`; grammar-fixture path helpers unified into a dev-only `hume-test-fixtures` crate; `HUME_REQUIRE_GRAMMAR_FIXTURES` env var closes the vacuous-pass gap.** `InlineParseBackend` (`hume-treesitter/src/parse_worker.rs`) is `#[cfg(any(test, feature = "test-util"))]`. `scripts/fetch-test-grammars.sh` copies a monorepo grammar's (`markdown`, `markdown.inline`) `queries/` up to its fixture root after compiling, so every fixture has the same `tests/fixtures/grammars/<name>/queries/` layout regardless of subpath. Catalog-parsing path helpers (`skip_unless_grammars`/`skip_unless_file` gating) live in `hume-test-fixtures`, used as a dev-dependency by both `hume-treesitter` and `hume-editor`. Every grammar-fixture test gate routes through the same `skip_unless_*` helpers: skip with a note on a fixture-less local run, hard-panic when `HUME_REQUIRE_GRAMMAR_FIXTURES=1` (set in CI and `scripts/test-all.sh`, mirroring `HUME_REQUIRE_LIVE_GRAMMAR_E2E`). | One shared gating mechanism instead of duplicated/divergent per-crate helpers, so no grammar-fixture test can vacuously pass on a fixture-less machine without CI catching it. |
| `editor/` module layout | **Submodule dirs for name-clusters** (`buffer/`, `search/`, `syntax/`, `minibuf/`) | Suffix-named flat files (`buffer_store.rs`, `search_ops.rs`, `minibuf_history.rs`, `syntax_glue.rs`, …) encoded grouping in names instead of directories, and `editor/ops.rs` (buffer lifecycle) collided with the crate-level `ops/` (pure commands). Grouped into per-domain dirs; theme loading extracted to `editor/theme.rs`. Existing dirs (`commands/`, `keymap/`, `mappings/`, `registry/`, `completion/`) and `lifecycle.rs` deliberately untouched. |
| LSP design | **See `LSP.md`** | All LSP decisions and shared reference live in `LSP.md` (the hub); per-task implementation cards live in `docs/lsp/step-{0..4}.md`. |
| toml crate version | **Stay on 0.8** (`default-features = false, features = ["parse"]`) | `toml::Value: FromStr` in 1.x parses only a single value expression, not a full multi-key document — incompatible with `hume-engine`'s theme loader (`source.parse::<toml::Value>()` in `theme/loader.rs`). Bumping requires rewriting the loader against 1.x's document-parsing API (`toml::Table::from_str` / `toml_edit`) first. |
| Syntax highlighting | **Tree-sitter** | Incremental parsing, structural understanding. Enables text objects and structural navigation beyond just colors. Production-proven (Neovim, Helix, Zed, GitHub). |
| Key mapping | **Command-based** | Keys bind to named commands, not to other keys. No recursive/non-recursive distinction. Keymaps defined in Steel config. Supports nested keys for sequences/chords. |
| Editing model | **Select-then-act** | Motions create selections, actions operate on them. Multiple selections from day one (`Vec<Selection>`). Selections always inclusive — `anchor == head` is a 1-char selection, never a zero-width point. |
| Extend mode | **`e` toggle (primary) + Ctrl+motion (kitty bonus)** | Sticky mode; `e` mnemonic. Ctrl+motion rejected as universal modifier: fatal legacy-terminal collisions on 10 of 15 motion keys (`Ctrl+h`=Backspace, `Ctrl+[`=ESC, etc.). Alt rejected — types accented chars on macOS, physical layout issues on Windows. Kitty Ctrl+motion is a graceful bonus; explicit `Ctrl+letter` leaves use a `force_extend` flag instead. |
| Line selection | **`x`/`X` (walk down/up lines)** | `x` selects current line including `\n`; repeated `x` walks to next. `Ctrl+x`/`Ctrl+X` accumulate lines (force_extend, works in both kitty and legacy). `Ctrl+e` flips anchor/head (works in Normal and Extend mode, and on legacy terminals); vim-style `o`-in-extend flip moved to `core:vim-keybind`. Extend is bidirectional — see next row. |
| Extend direction (`w`/`b`, `x`/`X`) | **Bidirectional: anchor-unit for words, anchor-line span for lines** | Opposite-direction presses shrink the selection back instead of only ever growing (Helix/Kakoune's extend only grows). Words: the anchor's word is re-derived fresh from its current position on every press and always kept whole — crossing it flips the selection's direction rather than truncating the word. Lines: an unaligned selection is first aligned to full lines (direction fixed by which key was pressed), then each press moves the *head*'s line by ±1 relative to the anchor's line; clamps at the buffer's first/last line are head-relative, not selection-end-relative. |
| Delete char at cursor | **`d` (no separate binding)** | In select-then-act with always-inclusive 1-char selections, `d` on a fresh cursor deletes the char under it — identical to Vim's `x`. |
| Terminal I/O | **termina** | Cross-platform. Handles raw mode, key/mouse events, and typed CSI/OSC escape sequences; decodes kitty CSI-u identically on every platform, including Windows (`ENABLE_VIRTUAL_TERMINAL_INPUT`). `hume-platform::terminal::SharedTerm` wraps a `termina::PlatformTerminal` behind a mutex, shared (cloned) between the render loop, the signal handler, and the inline-output bracket; blocking `poll`/`read` go through a cloned `EventReader` and never take the lock. Windows runs VT mode unconditionally — no legacy fallback — since HUME already requires true color and DEC 2026 sync output, which legacy conhost can't provide either; a pre-1809 console or a raw pipe (mintty without winpty) fails `terminal::create()` with a pointed error instead of degrading. |
| Rendering | **ratatui as diffing engine** | Cell-level rendering via ratatui's double-buffer diffing. No widgets. Immediate-mode thinking with retained-mode optimization. Backend is `ratatui-termina`'s `TerminaBackend`. |
| Terminal protocol | **Prefer kitty keyboard, fall back** | Probe at startup; use when available for unambiguous key encoding and modifier reporting, legacy encoding otherwise. Unix probes over its own `/dev/tty` side channel (independent of the main `SharedTerm` event reader) and additionally checks the XTVERSION reply against a terminal whitelist (WezTerm/kitty/ghostty/foot) for terminals that support kitty push but don't answer the `?u` query. Windows writes the same kitty query through the live `SharedTerm` and waits for termina's `EventReader` to decode a `ReportFlags` reply (or a DA1 fence with none), so a `true` verdict means kitty-encoded keys will actually decode. |
| Documentation | **Markdown + auto-generated command reference** | Hand-written Markdown guides for concepts. Command reference auto-generated from Rust doc comments. In-editor `:help` renders Markdown in a read-only buffer. |
| Plugin trust model | **Full trust, Helix-aligned; no sandbox** | Every plugin runs with Steel's full stdlib (`steel/process`, `steel/filesystem`, `steel/ports`) — a plugin can always spawn arbitrary processes; this matches the Helix plugin ecosystem's own trust model. PLUM (`runtime/plugins/core/plum/*.scm`) is written against Steel's own `command`/`spawn-process`/`which`/`steel/filesystem`. A small set of sandbox-free *utility* builtins survive where a Scheme rewrite would only make platform-conditional logic worse: `hume-target`/`data-dir`/`runtime-dir`/`path-join` (editor-integration info + Windows UNC stripping), `unpack-gz`/`unpack-zip` (chmod + archive-format selection), `sha256-file` (per-platform hashing tool selection), `compile-grammar!` (Windows C-compiler probing), `acquire-install-lock!`/`release-install-lock!` (O_EXCL install lock), and `run-inline-output!` (process-group-isolated spawn — Steel's `spawn-process` has no `setpgid`/`pre_exec`, needed because `#:inline-output` commands run with terminal raw mode off, so an unisolated child would be killed by the same Ctrl+C meant to interrupt only it). |
| Fuzzy finder scriptability (`docs/FUZZY-FINDERS.md`) | **Steel-defined pickers only; no native picker definitions** — defaults (files, buffers) ship as a `core:pickers` Steel plugin; enumeration-scale sources are external commands (`git ls-files`, `fd`) spawned via `picker-source-spawn!`, whose stdout lines stream Rust-side directly into the picker store (bulk never enters the Steel VM; Steel supplies argv and parses the one accepted line) | Per-keystroke perf is identical whether pickers are native or Steel-defined, since Steel only ever touches picker open/accept, not the render/filter path; a fixed native set fails the motivating finders (live grep, "find unstaged files"). Full rationale in `docs/FUZZY-FINDERS.md`. |
| Theming | **Hierarchical scopes** | Dot-notation scopes (`keyword.function`, `ui.cursor`) with automatic fallback. Helix scope names for theme compatibility. Helix TOML theme format including `inherits` chains and `palette`. |
| Package manager | **PLUM (PLUgin Manager) — Steel script, swappable** | Core plugin (`core:plum`). Two namespaces: `core:name` (bundled) and `username/repo` (Git-based, no registry). Every plugin must appear in `init.scm` via `(load-plugin …)` or `(declare-plugin …)`. Disabling PLUM just removes management commands. |
| Lazy plugin loading | **Plugin manifests; load-once (no unload)** | `(load-plugin name)` = eager; `(declare-plugin name …)` = lazy manifest declaring `#:commands` / `#:events` / `#:languages` activation entries. Fail-fast on first error; no retry until `:reload-config`. No unload. |
| Plugin configuration | **`#:config` keyword; `(plugin-config)` read-back** | Both `load-plugin` and `declare-plugin` accept `#:config` (an opaque value, typically a hash), stored per-plugin at declare/load time. The plugin body reads it back via `(plugin-config)`, resolved from the top of the plugin attribution stack — identical for eager and lazy bodies since both push there for the duration of the eval. `core:vim-keybind` uses this for a `change-to-eol` (`'on`/`'smart`/`'off`) switch controlling its one default-shadowing binding (`C`). |
| Plugin namespace isolation | **One Steel module per plugin (`require`)** | Each plugin loads via `(require "<abs-path>")` giving its own module namespace. Cross-plugin calls go through `call!` only. |
| `#:inline-output` bracket entry | **Lazy — opened on first real output, not eagerly at dispatch** | A command body whose only branch is `log!` (e.g. `:lsp-install` on an already-installed, up-to-date server) must not flash an empty alt-screen and force an unneeded keypress, since `log!` only ever reaches `pending_messages` (the status line), never stdout. `EditorState.inline_output` is a state machine (`Inactive`/`Armed`/`Entered`/`Headless`); `OutputHost::ensure_inline_output_screen` (reached via `EditorHost::output()`, `None` on hosts with no live TUI) is the single trigger, called by the builtins that actually write to the terminal — the gated print shims (`displayln`/`display`/`print`/`println`/`newline`/`write`/`write-string`/`write-char`/`simple-display`/`simple-displayln`, gated on `is_inline_output`, not `is_init` — init prints run pre-terminal), `run-inline-output!`, `compile-grammar!`, `unpack-zip` — immediately before they produce output. A command that never calls one of these never opens the bracket at all; `log!`-only branches report on the status line like any ordinary command. A plugin writing to the terminal through some other path (Steel's own `spawn-process`/ports with inherited stdio, not piped) gets no pre-opened screen and can corrupt the TUI — PLUM only uses the instrumented builtins, and `runtime/plugins/core/plum/lib.scm`'s own contract reserves raw inherited-stdio `spawn-process` for non-`#:inline-output` commands only. The print-gate mechanism (why a plain top-level shadow misses code inside a `(require "path.scm")`'d plugin module, and the `PRINT_GATE_SHIMS` fix via `Engine::set_prelude_string`) is documented at `hume-scripting/src/builtins/io.rs`'s module doc; see `builtins::io::tests::required_module_displayln_call_reaches_the_gate` / `required_module_other_print_fns_reach_the_gate` for the regression guards. |
| Plugin attribution / lifecycle | **Keep attribution, drop ledger; fail-fast** | `PluginId` / `Owner` / `PluginStack` / `cmd_owners` track who registered what. Mutation ledger and per-plugin rollback removed — Neovim/Helix ship no clean per-plugin unload. `:reload-config` rebuilds from scratch. |
| Command dispatch args | **Variadic `call!`; no side channel** | `(call! name args…)` dispatches to Steel or native commands. Arity-based injection: 0 params → nothing, 1 → count, 2/variadic → count+extend. |
| `call!` unknown-command severity | **Logs `Error`, still no-ops (no Steel error raised)** | Matches typed `:` command severity (`command_mode.rs`) — an unreachable `call!` target is a plugin bug (typo or missing dependency), not merely notable. Kept as a no-op rather than a raised error: raising from `%call-native!` (a native builtin) risks the with-handler re-raise/VM-panic hazard on the Steel 0.8.2 VM, and edits already applied earlier in the body are undoable regardless (each inner edit records its own undo revision — no rollback exists either way). Keybind-dispatch misses are a separate path (`hume-editor/src/editor/dispatch.rs`) and stay `Warning`. Plugin-dependency checks in `plugins.md` are two-tier: `(loaded-plugins)` for a dependency needed at plugin-body top level, `(declared-plugins)` for one only reached from a key-fired command (where `call!`'s on-demand lazy activation makes "declared" sufficient). |
| Indent queries | **Helix format (`indent.scm`)** | Reuse Helix per-language indent queries directly. Avoids reinventing a query format; gives a large library of languages for free. |
| Syntax highlight query granularity | **Per-line queries from tree root** | Each visible line runs the highlight query clipped via `set_byte_range` — cost is O(tree depth + line content), and span lookup stays a pure function of `(tree, rope, line)`: callable from anywhere in any order (render loop, future minimap/export, tests). Revisit bar: profiling shows query cost in the frame budget (e.g. under smooth scrolling). |
| Unicode handling | **Grapheme clusters from day one** | All motions and selections use `unicode-segmentation`, not bytes or chars. Retrofitting is expensive. |
| Keymap defaults vs config | **Hardcoded defaults, config overrides** | Defaults in Rust as SSOT. User config (Steel) provides overrides only. Editor always works with zero config; missing or unparseable config silently uses defaults. |
| Jump-list eligibility | **Flag on `MappableCommand`** | `jump: bool` field (like `repeatable`) lets every command — Rust or Steel — declare jump intent at registration. A `const` list can't capture plugin commands that move the cursor directly. |
| Register linewise flag | **Heuristic: detect at paste time** | Trailing `\n` signals linewise content. No explicit flag stored; natural upgrade path if heuristic proves insufficient. |
| Paste on selection (`p`/`P`) | **Replace selection, no swap** | `p`/`P` on cursor inserts normally; on a multi-char selection, replaces it. Displaced text not written back — kill ring gives access to previous content. |
| Register `'c'` (clipboard) | **Editor layer** | Requires OS clipboard integration; belongs in editor layer, not core. |
| Read-only registers (`.`, `%`, `#`) | **Editor layer** | Require editor-level state (mode tracking, open file list); not implementable in core. |
| Register naming | **Mnemonic letters, `0`–`9` named storage** | `k` = kill-ring head, `c` = clipboard, `b` = black hole, `s` = search, `q` = default macro. 10 named registers (`0`–`9`) for symmetric in-memory storage. Default register (`"`) is internal. Kill ring reached via `"k` or `[`/`]` cycling. |
| Macro model | **Register-based, Vim-style, with `Q`/`q` UX** | Macros stored in registers. `q` = default. `QQ` records into `q`; `qq` replays. `Q` for record (deliberate setup); `q` for replay (hot path). Multiple saved macros without the full `a`–`z` Vim namespace. |
| Register picker UI | **Editor layer** | Popup listing registers with descriptions and contents when register prefix pressed. Makes register names discoverable without memorisation. |
| Dot-repeat scope | **Selection recipe + action** | Replays: last selection-establishing command + extend steps + editing command + insert keystrokes. Plain navigation not recorded. Recipe discriminated by `Selection::is_collapsed()` after each Motion/Selection command. Steel commands opt in via `#:repeatable #t`. Mutually exclusive with `#:inline-output`. |
| Surround operations | **`ms` + smart `r` (select-then-act, no `md`/`mr`)** | `ms` + char selects surrounding delimiters as two cursor selections. Delete = `ms(` → `d`. Replace = `ms(` → `r[`. Smart `r` maps open→open, close→close; symmetric delimiters use selection index as tiebreaker. Rejected: Helix `md`/`mr` which bake selection+action together, violating select-then-act. |
| Word motions (`w`/`b`/`W`/`B`) | **Select whole word, optionally with one adjacent whitespace run (default on)** | `w` selects the next word entirely; `b` selects the previous word entirely. `e`/`E` removed as redundant. Diverges from Helix, whose `w` selects the gap traversed from the old cursor position through the trailing whitespace up to (not including) the next word start — HUME selects the destination word itself. Default behavior additionally covers the destination word's *leading* whitespace, gated by the buffer-scoped `word-selects-whitespace` setting (`#t` by default; `#f` restores bare-word selection) — except the first word of a line, which takes its *trailing* whitespace instead, since any leading run there is indentation and must never be absorbed; EOL is never consumed on either side. One rule, shared by every word+whitespace span in the editor: `mm`/`MM` (gated by the setting) and `maw`/`maW` (never gated — always on) select identical spans; `miw`/`miW` are the bare/inner form, also never gated. With the cursor on whitespace, `mm`/`maw` snap to the adjacent word (following preferred, preceding fallback) under the same rule — newlines and indentation under the cursor are never selected. Extend mode honors the setting the same way Move does — the anchor's unit (and a backward-growing target's landing edge) includes its whitespace bookend too. |
| Multi-buffer scope (M7) | **List + switch only; no splits or tab UI** | Multiple open buffers, `:e`/`:bnext`/`:bprev`/`:bd`. Splits and tabline deferred — require a layout engine. |
| Disjoint-borrow refactor | **Logic in free functions over sub-struct borrows, not `&mut self` methods on outer `Editor`** | `Editor` is a thin wrapper over three sibling sub-structs — `scripting`, `state` (`EditorState`, all command-mutable data), and `view` (`EngineView`). The split exists so command/editing logic can take the narrowest borrow (`&mut EditorState`, `&EngineView`, or individual fields) as a free function, letting Rust prove borrows disjoint instead of forcing workaround clones. A `&mut self` method on the *outer* `Editor` borrows all three at once, blocking that — such methods are reserved for lifecycle entry points, cross-cutting orchestration, and thin delegators. Enforcement is structural: the borrow checker rejects cross-sub-struct access from a sub-borrow, so a new whole-`Editor` borrow appears as an explicit clone or a new outer `&mut self` method in review — no separate lint. |
| Kitty push order on init | **Push after entering alt screen** | Some terminals maintain a per-screen keyboard stack. Pushing before `EnterAlternateScreen` lands flags on the primary screen's stack, which key reads don't consult. |
| SHIFT normalization | **Strip bare SHIFT for any Char** | Terminals that don't honour `REPORT_ALTERNATE_KEYS` send shifted punctuation as `Char + SHIFT`, missing trie bindings. Strip SHIFT for any `Char` when SHIFT is the only modifier (`Ctrl+Shift` keeps CONTROL; `Shift+Tab` = `BackTab` is not a `Char`). |
| Kill-ring whitespace collapse | **Overwrite pure-whitespace head in place** | On push, if the ring head is pure-whitespace, the new entry overwrites it instead of taking a fresh slot. Keeps swap-junk from filling the ring; the whitespace stays retrievable until the next push. |
| Tab handling | **One knob (`tab-style`), reuse `tab-width`** | Tab key inserts `\t` (hard) or spaces to next tab stop (soft). `tab-width` reused for both rendering and Tab-key spacing. Vim's four-knob `shiftwidth`/`softtabstop` model rejected as too complex. Enter copies leading whitespace verbatim. |
| Diff module | **histogram + Myers fallback, `similar` hidden** | `diff_lines`: histogram with wall-clock deadline, falls back to Myers on timeout. `diff_words`: Myers over UAX #29 word-boundary tokens with deadline. `similar` is a hidden impl detail — public types owned by `hume-editing` so consumers never depend on the backend. |
| `:split` / `:vsplit` direction mapping | **`:split` = top/bottom stack → engine `Direction::Vertical`; `:vsplit` = side-by-side → `Direction::Horizontal`** | Vim convention. Engine `Direction` partitions the named axis, so the enum name is the inverse of intuition — a named constructor/helper prevents bugs. |
| Split buffer | **Duplicate focused pane's buffer** | `:split`/`:vsplit` mirror the focused pane's buffer; optional `<path>` arg opens a different buffer. Matches Helix multi-pane contract. |
| Jump list on split | **Same-buffer split clones source; diverges thereafter** | A same-buffer `:split`/`:vsplit` clones the source pane's `JumpList` (entries + cursor) so the new pane can Ctrl+O back to pre-split positions. Different-buffer split starts empty. After the split each pane's jumps mutate independently. |
| Close-pane | **`Ctrl+p c` / pane-aware `:q`; no `:close`** | Prunes the focused leaf, collapses the parent `Split`, refocuses the sibling. `:q` closes the focused pane when others are open; only falls through to its existing buffer/quit logic on the sole pane. `Ctrl+p c` on the sole pane warns instead of quitting — `:q` alone owns quitting. |
| `wrap_mode` scope | **Lives on `Pane`; `EditorSettings.wrap_mode` is init-default only** | Wrap is a view property, not a document preference. Runtime per-pane override via `:set pane wrap-mode=<value>`; `Pane` also carries `saved_wrap_mode` (always a wrapping variant) so `:wrap` toggle-on restores whatever mode the pane last wrapped with instead of hardcoding `indent`. Steel-side per-pane/per-buffer `set-option!` still deferred — only `Global` scope is scriptable. |
| Dynamic decoration content (engine) | **Per-frame text arena for cells; `Cow` for gutter; `Box<str>` for whitespace glyphs** | `CellContent::{Virtual,Indicator}` hold `{start: u32, len: u16}` ranges into `FormatScratch::virtual_texts` (cleared per buffer line/virtual row) instead of `&'static str`, so `Grapheme` stays `Copy` while decoration text (LSP hints, Steel icons) can be computed at runtime. `InlineInsert.text` and `VirtualLine::{text, segments}` are owned (`String`); the pipeline builds virtual-line graphemes itself from `text`+scoped byte-range `segments` rather than trusting provider-built `Grapheme`s. `GutterCellContent::Text(Cow<'static, str>)` replaces `Static`/`Number`. `WhitespaceConfig`'s three glyph fields are `Box<str>`. |
| Sign column tie-breaking (`SignColumn`) | **Higher `priority` wins; ties go to the later-registered source** | `SignColumn` merges `Sign`s from multiple `SignSource`s (diagnostics, git, breakpoints, bookmarks) into one narrow gutter column via `max_by_key(priority)`, which keeps the *last* max on ties — i.e. registration order breaks ties, not first-registered-wins. `GutterCell.scope` gained a `GutterScope::{Name(Scope), Id(ScopeId)}` split so `Sign` (and any future fast-path gutter provider) can carry an already-interned `ScopeId` like `HighlightSource`/`InlineInsert` do, instead of forcing every gutter column through the by-name resolve path. |
| Startup ordering (b/w→highlighted flash) | **Scripting init runs before terminal init** | `init_scripting` (Steel VM boot + `init.scm`) runs while the terminal is still in normal/cooked mode — the shell stays visible instead of an unthemed alt-screen frame, and the alt-screen only opens once the editor is fully themed. The kitty keyboard probe is split out of `terminal::init` into `terminal::probe_kitty()` (runs on the normal screen, raw-mode-only) so `set_kitty_support` can still install kitty-only default keybinds *before* `init.scm` evaluates user `bind-key!` calls — this ordering is load-bearing (`apply_kitty_defaults` does plain overwriting `bind_leaf` calls). The end-of-init `detect_and_set_language` loop posts the initial buffer's parse. Steel/`im-rc`/`lasso` crates are pinned to `opt-level = 3` in the dev profile. Accepted trade-offs: keys typed during the pre-alt-screen window echo to the shell instead of reaching the editor; `init.scm`'s `(set-option! 'mouse-enabled …)` takes effect at startup. |

## Open Questions

| Question | Context |
|----------|---------|
| Multiline quote text objects | Quote text objects (`i"`, `i'`, `` i` ``) are line-bounded because the parity scan gives wrong results when earlier lines contain unmatched quotes. Brackets don't have this problem (asymmetric delimiters allow depth tracking). Tree-sitter can resolve the ambiguity — use syntax-aware matching when a grammar is loaded, fall back to line-bounded parity otherwise. |
| Register paste count mismatch | When yank uses N cursors but paste uses M≠N, Helix falls back to pasting the full register at every cursor. Explore alternatives with real usage data (e.g. cycling slots, clamping to last slot, user-facing warning). Decide after more real usage. |
| Common-prefix auto-extend on Tab | Readline/bash behaviour: on Tab with ≥2 candidates, first extend the input to their shared prefix before opening the popup. Current behaviour skips straight to cycling. Small UX polish; decide after more real usage whether the extra keystroke saved is worth the surprise of input mutating mid-type. |
| Plugin-defined languages × lazy loading | Language identity/detection is HUME-owned (`runtime/scheme/languages.scm`, eager). A plugin keying `#:languages` off an *existing* language works fine. But a plugin that defines its **own** language must register that identity **eagerly** — a lazy body cannot be the sole provider of its own activation language (chicken-and-egg). Deferred to a dedicated brainstorm. |
| `llvm-mir` / `llvm-mir-yaml` grammar mismatch | Inherited from Helix: `llvm-mir-yaml` defines the `.mir` extension but delegates to the `llvm-mir` grammar (no separate compiled grammar). `llvm-mir` itself has no extension binding. Track upstream; no HUME-specific fix needed until then. |
| Undercurl blocked on ratatui underline-shape support | `UnderlineStyle::{Wavy,Dotted,Dashed}` all collapse to plain `Modifier::UNDERLINED` in `From<ResolvedStyle> for ratatui::style::Style` (`types.rs`) — ratatui's `Modifier` bitflags have no underline-shape bits, regardless of backend; the current backend (termina) can represent the shape at the protocol level (`style::Underline`), but there is no injection point between the engine and the terminal to reach it. Deferred: the engine model and theme loader are already correct, so this needs no engine change once ratatui adds underline-shape support — revisit then. |
| `ProviderSet::remove` unwired | Engine primitive `ProviderSet::remove` (`hume-engine/src/providers.rs`) is implemented and tested but has no editor call site — provider ids returned by `build_pane`'s `add_*` calls are discarded, and nothing dynamically registers/deregisters a provider. Wire it when the first real consumer lands: (a) Steel provider-registration builtins (plugin-added columns/overlays), or (b) a gutter-visibility `:set` toggle that removes/re-adds a built-in column. Until then, capturing ids on the pane would be speculative. |
| Search-state clobbering from Steel | Exposing search commands (`search-next`, `select-all-matches`) to Steel lets a plugin's own pattern overwrite the *user's* interactive search state (last pattern, direction) — after the plugin runs, pressing `n` jumps to the plugin's pattern instead of the user's. Decide before exposing: pattern-taking variants that don't touch shared state, or documented clobbering. |
| Mark/bookmark drift across edits | A char offset returned by `(current-selections)` and stored by a plugin (bookmark, saved position) goes stale as edits land before it's used — the index is still a valid grapheme boundary, just pointing at the wrong place. Real marks need positions mapped through `ChangeSet`s as edits happen; decide where that mapping lives and which stored positions opt in, or document verbatim store/restore as edits-must-not-intervene. |
| Snap-vs-error policy for future selection setters | A future `set-selections!`/`goto-char!`-style builtin must handle out-of-range or mid-cluster input from Steel (e.g. computed from string search offsets). Two options: snap to the nearest valid grapheme boundary (forgiving, but can silently hide a plugin bug), or raise (fail-fast, but breaks a legitimately-drifted stored position). Decide per call site before the first setter lands — no setter exists yet, so nothing is blocked on this today. |

### M10 — Splits (complete)

- **Splits & pane focus (`:split` / `:vsplit` / pane focus commands)**: `LayoutTree::Split` mutation, per-pane render, directional and next-pane focus, close-pane, seam dividers with focus dimming, and per-pane `wrap_mode` (on the engine `Pane`, `hume-engine/src/pane.rs`, as the SSOT) are all wired.
  - [x] **`LayoutTree` mutation primitives** (`hume-engine/src/pipeline.rs`): `split_leaf(target, new_pane, direction, ratio) -> bool` replaces `Leaf(target)` with `Split { direction, ratio, (Leaf(target), Leaf(new_pane)) }`; `remove_leaf(target) -> Option<PaneId>` prunes a leaf, collapses the parent `Split` onto its sibling, and returns the sibling id (`None` if sole leaf).
  - [x] **`:split`/`:vsplit` bodies** (`hume-editor/src/editor/commands/typed_misc.rs`): `:split` → `Direction::Vertical` (stacked), `:vsplit` → `Direction::Horizontal` (side-by-side). `open_pane(focused_buffer_id())` → `view.layout.split_leaf(focused_pane_id, new_pid, dir, 0.5)`. Optional `<path>` arg opens that buffer then splits. Normal-mode only.
  - [x] **Multi-pane render / `prepare_frame`** (`hume-editor/src/editor/lifecycle.rs`): the rope and pane-settings closures in `render_into` resolve every pane's `buffer_id`/settings, not just the focused one; `prepare_frame` scroll-sync iterates all panes from `collect_rects_into`.
  - [x] **Directional pane-focus** (`hume-editor/src/editor/commands/jump.rs`): `EngineView` caches the last-rendered `Vec<(PaneId, Rect)>` during `prepare_frame`. `cmd_pane_focus_{left,right,up,down}` use that cache + nearest-rect-edge from the focused pane; `cmd_pane_focus_next` cycles by tree DFS order.
  - [x] **Close-pane command**: native `pane-close` (`hume-editor/src/editor/commands/jump.rs`), bound `Ctrl+p c`. `:q` (`typed_quit`) is pane-aware: if `view.panes.len() > 1` it closes the focused pane (`close_focused_pane` in `commands/mod.rs` — `LayoutTree::remove_leaf(focused)` → refocus returned sibling → drop the four per-pane maps), skipping the dirty check (buffer stays open in the buffer list); otherwise it falls through to single-pane buffer/quit logic. `pane-close` on the sole pane warns `"cannot close last pane"` and no-ops — `:q` alone owns quitting.
  - [x] **`wrap_mode` on `Pane`** (`hume-engine/src/pane.rs`, `hume-engine/src/pipeline.rs`, `hume-editor/src/editor/lifecycle.rs`): the engine `Pane` carries `pub wrap_mode: WrapMode`, seeded from `EditorSettings::wrap_mode` at every pane-construction site. `resolve_pane_settings` sources `PaneRenderSettings.wrap_mode` from `pane.wrap_mode`. `Editor::focused_wrap_mode()` is the SSOT read helper (scroll-sync, mouse, `focused_format_context`, `:toggle-soft-wrap`). `:set` key `wrap-mode` lives in `global{}`, not `buffer{}` — `:set buffer wrap-mode=…` rejects as global-only.

End-user docs (`user-manual/docs/commands.md`, `user-manual/docs/key-reference.md`, `user-manual/docs/files-and-buffers.md`) cover the `Ctrl+p c` chord, pane-aware `:q`, and a "Splits and panes" concept section.
  - [x] **Pane seam dividers + focus dimming** (`hume-engine/src/pipeline.rs`, `hume-engine/src/render.rs`, `hume-editor/src/editor/commands/typed_misc.rs`): `split_rect` reserves a 1-cell seam between sibling panes (`LayoutTree::collect_seams_into`), drawn `│`/`─`, muted by default; the sub-segment adjacent to the focused pane is accent-colored (`focused_seam_segment` — an intersection, not a whole-seam bool, so a seam shared by several sibling panes only lights up beside/above the focused one).
