# HUME — LSP Support

Design and task breakdown for Language Server Protocol support. All LSP decisions live here (moved out of `ROADMAP.md`, which keeps a pointer).

## Overview

**Goals**, in order:
1. **Community-extensible**: LSP features live in Steel so plugins can add features, server integrations, and custom UX without touching Rust.
2. **Snappy on big-realistic workloads**: rust-analyzer on a large crate, 100k-line files, 5k-diagnostic bursts, 1k-item completion lists, large terminals.

**Architecture: Steel on the control plane, Rust on the data plane.** The split is a *frequency cut*, not a per-feature assignment:

- Runs **per user intent** (a keypress-triggered command, a server response arriving, a menu selection) → Steel. A Steel dispatch costs tens of microseconds against a 16 ms frame budget.
- Runs **per frame, per scroll row, or over unbounded collections** (rendering, diagnostic bursts, completion filtering, position math over edits) → Rust.

Two structural guardrails keep the experience snappy *by construction*, not by discipline:
- **Bulk data never crosses the Rust↔Steel boundary on recurring paths** (per-frame, per-keystroke, per-scroll). Diagnostics and completion items live in Rust-side stores; Steel sees signals, bounded subsets, and policy knobs. A one-time ingest at user-intent frequency (e.g. a completion response passing through Steel into the store, B8) is the calibrated exception — P8 measures whether it holds at 1k items.
- **Steel never runs on the render path.** Steel writes data stores; Rust providers render from them every frame.

Rust therefore ships a *platform* — transport, document sync, stores, render providers, a generic LSP bridge, scriptable UI widgets — and the features themselves are Steel code in a `core:lsp` plugin: send request → transform response → call a UI/store builtin. A community plugin author writes the exact same three-line shape.

**v1 feature set**: diagnostics, completions, hover, go-to-definition (+ declaration / type-definition / implementation), rename, references, signature help, formatting, code actions, inlay hints.

**Non-goals for v1**: semantic tokens, snippet placeholder navigation, `workspace/symbol`, document symbols, code lens, DAP, multiple servers per language or buffer.

**Implementation shape** (five macro-steps):
1. **Step 0 — Prerequisites**: workspace groundwork (serde, position mapping, event-loop wake + timers, encodings, URIs, the boundary-cost spike).
2. **Step 1 — LSP core (Rust data plane)**: the `hume-lsp` crate (transport + client) and editor glue (document sync, diagnostics store, registration).
3. **Step 2 — Steel platform**: the generic bridge, codec, stores, edit/navigation primitives, and hooks that let Steel drive everything.
4. **Step 3 — UI surfaces**: scriptable widgets (popup, menu, drawer) and store-fed render wiring (underlines, signs, virtual lines).
5. **Step 4 — Features (Steel)**: the `core:lsp` plugin composing Steps 2–3 into user-facing features.

Steps 1–3 are ordered by dependency but Step 4 tasks unlock incrementally — each feature can land as soon as the primitives it composes exist.

## Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| LSP architecture | **Hybrid: Steel control plane, Rust data plane** | Rust owns transport, JSON-RPC, document sync, bulk stores, and rendering. Steel owns behavior: every user-facing feature is Steel code composing Rust primitives. The boundary is frequency: per-user-intent work may be Steel; per-frame / per-scroll / unbounded-collection work must be Rust. Maximizes community extensibility without sacrificing latency. |
| Feature delivery | **Generic LSP bridge + `core:lsp` plugin, not hardcoded Rust features** | `(lsp-request server method params callback)` / `(lsp-notify …)` / `(on-lsp-notification method handler)` make any protocol method reachable from Steel. v1 features ship as the `core:lsp` plugin using the same public surface plugins get — dogfooding guarantees the bridge is complete. Rust volume is similar to hardcoding v1 (generic infra costs more up front), but marginal feature cost afterward is a Steel file anyone can write. |
| Bulk-data guardrail | **Bulk never crosses the boundary on recurring paths** | Diagnostics are ingested, stored, and remapped in Rust; Steel receives change *signals* and pulls bounded subsets (visible lines, top-N). Completion items live in a Rust store with a Rust per-keystroke filter; Steel orchestrates and sees the top-N. The one crossing allowed is a per-user-intent ingest (a completion response flowing through the B2 callback into `completion-begin!`) — if the P8 spike shows that's too slow at 1k items, `lsp-request` grows a flag routing the raw response straight into the store, handing Steel a handle instead of items. |
| Render decoupling | **Data-driven decoration stores; Steel never on the render path** | Steel setters (`set-inlay-hints!`, `set-signs!`, `set-virtual-lines!`, …) write Rust-side stores; the existing engine providers (`HighlightSource`, `SignSource`, `VirtualLineSource`, `InlineDecoration`) render from them each frame with zero Steel involvement. |
| UI widgets | **Rust-rendered, Steel-fed** | Cursor popup, selection menu, drawer list are generic Rust widgets taking content + callbacks from Steel (`show-popup!`, `show-menu!`, `show-drawer-list!`). LSP is their first client, not their owner — any plugin can use them. |
| Symbol rename | **LSP-first, tree-sitter fallback** | `textDocument/rename` when LSP active; falls back to tree-sitter local rename via `locals.scm` — file-local only but scope-correct. Same keybinding in both cases. |
| Position remapping through edits | **Batch `PosMapCursor`, never per-position** | Diagnostic ranges, bookmarks, and any stored positions must be remapped through edits with the batch primitive: widen `ChangeSet`'s `PosMapCursor` (`hume-editing/src/changeset/mod.rs`) from `pub(crate)` to `pub` and map sorted position lists through one cursor. Per-position one-shot mapping reintroduces the O(positions × ops) cost that `translate_in_place` was migrated off. |
| Protocol types | **`lsp-types` crate** | De-facto standard (Helix, rust-analyzer ecosystem), spec-tracking, serde-based. Hand-transcribing the LSP spec is weeks of error-prone tedium. Brings `serde`/`serde_json` into the workspace (which also fires the toml 0.8 → 1.x upgrade trigger). |
| Transport concurrency | **std threads + mpsc; `LspBackend` trait mirroring `ParseBackend`** | Per server: reader thread (blocks on server stdout), writer thread (stdin), stderr logger. Messages cross to the main loop via mpsc; `prepare_frame` drains; `has_pending()` switches the event loop to `poll(timeout)` — byte-for-byte the `ThreadedParseBackend` pattern. No tokio: transport concurrency is never the bottleneck (heavy JSON parse lands on reader threads off the main loop; incremental `didChange` is proportional to the edit, not the file), and a runtime would split a fully-sync codebase into two concurrency idioms. The trait boundary is the insurance policy. Cost accepted: request timeouts are hand-rolled (deadline check at drain time). |
| Crate boundary | **New `hume-lsp/` crate** | Follows the `hume-treesitter` precedent: transport, JSON-RPC codec, and client state have zero `Editor` dependency. Depends on `hume-editing` (ChangeSet → didChange conversion) + `lsp-types`; acyclic. Editor glue (drain, stores, builtins, hooks) stays in `hume-editor`. |
| Server instance scope | **One per (language, workspace root)** | First buffer open whose (language, resolved root) pair has no running server spawns it (C3 + C5 handshake); later buffers with the same pair attach. Correct `rootUri` when two projects share a session; the diagnostics store already keys by server. |
| Position encoding | **Negotiate `utf-8`, fall back to UTF-16 conversion** | LSP defaults to UTF-16 code-unit columns; 3.17's `positionEncoding` capability lets client and server agree on `utf-8`. HUME is char/grapheme-based, so both paths need conversion helpers; ropey 1.6 provides `char ↔ utf16_cu` primitives (`char_to_utf16_cu` / `utf16_cu_to_char`, unconditional — no feature flag in 1.x) for the fallback. Never assume byte == column. |
| Timers | **Timer wheel in the event loop; `(after ms thunk)` + debounced hooks in Steel** | The loop already degrades to `poll(timeout)` when async work is pending; a nearest-deadline timer wheel bounds that timeout naturally. Required for debounced inlay-hint refresh, signature-help triggering, and completion debounce — without it, scroll- and keystroke-driven Steel work would fire unthrottled. |

## Open Questions

| Question | Context |
|----------|---------|
| Diagnostics exposure granularity | Rust ingests/stores/remaps (decided). Open: exactly what Steel pulls — per-line visible subset, per-buffer summaries, full list under a size cap? The P8 spike (JSON↔SteelVal throughput at 100/1k/5k items) decides where the cap sits. |
| Steel completion scorer budget | Rust does prefix/fuzzy filtering (decided; matches the existing "fuzzy scoring is a plugin concern" ROADMAP note for minibuffer). Open: the optional Steel scorer hook — score all candidates (cost unknown until P8) or re-rank Rust's top-N only? |
| Hover surface | Cursor popup vs Class B bottom drawer. Likely: popup primary, drawer for long docs / scrollback. Decide when U4/U6 land. |
| Snippet completions | v1 strips `${1:...}` placeholders to plain text. Confirm acceptable UX for rust-analyzer (which snippet-ifies aggressively) at F3. When full support lands (Future): placeholder *parsing* could be Steel; the insert-mode tabstop state machine with multi-cursor placeholder selections is likely Rust. |
| Server crash policy | Manual `:lsp-restart` only, or bounded auto-restart (e.g. 3 attempts with backoff)? Start manual-only; revisit with real usage. Policy knob belongs to Steel either way. |
| WorkspaceEdit on unopened files | Rename/code actions can touch files with no open buffer. Open-as-buffer (undoable, dirty, user saves) vs direct fs write (atomic but bypasses undo). Leaning open-as-buffer for undoability; needs a policy for the resulting pile of dirty buffers. Decide at B6. |
| `workspace/configuration` flow | How Steel user config reaches servers: `register-lsp-server!` `#:settings` blob answered verbatim to `workspace/configuration` requests + sent as `didChangeConfiguration`? Decide at C8. |
| `$/progress` | Servers report indexing progress. Statusline spinner element vs message-log only. Decide at U3. |
| `workspace/didChangeWatchedFiles` | Ties to the existing "File watcher" Future item in ROADMAP — LSP may be the trigger that promotes it. Not required for v1. |
| Multiple servers per language | v1: exactly one server per language. The diagnostics store keys by (server, buffer) so the door stays open. |
| `set-extra-highlights!` tier | Generic plugin spans need a `HighlightTier`: new variant vs reusing an existing one (Syntax / SearchMatch / Diagnostic / BracketMatch). Decide at U1 when wiring the provider. |

## Step 0 — Prerequisites

Workspace groundwork with no LSP-visible behavior. Each item independently landable and testable (exception: P6 lives in `hume-lsp` and needs C1's crate scaffold first). **Do P8 (spike) first** — its numbers calibrate the bulk-data boundary decisions in Steps 1–2.

- [ ] **P1 — serde + serde_json workspace deps.** Add to `[workspace.dependencies]`. This fires the recorded toml upgrade trigger: evaluate moving `hume-engine`'s `toml = "0.8"` to 1.x in the same pass or as an immediate follow-up.
- [ ] **P2 — Batch position mapping.** Widen `PosMapCursor` (`hume-editing/src/changeset/mod.rs`) from `pub(crate)` to `pub`; add a documented API for mapping a sorted position list through one cursor pass. Tests: positions before/inside/after each op kind; sorted-input invariant.
- [ ] **P3 — Generalized event-loop wake.** The loop only degrades from blocking `event::read()` to `event::poll(8ms)` when `parse_worker.has_in_flight()` (`lifecycle.rs`). Compose that predicate over all async sources (parse worker, LSP client, timer wheel), and give `prepare_frame` a drain slot for LSP messages next to `reparse_stale_buffers`. Shape it so adding a source is one trait impl, not another hand-written `||`.
- [ ] **P4 — Position encoding conversion.** Rope char offset ↔ LSP `(line, character)` for both `utf-8` and `utf-16` encodings. Ropey 1.6 exposes `char_to_utf16_cu` / `utf16_cu_to_char` unconditionally (no feature flag). Lives near the rope helpers in `hume-editing`. Tests: multi-byte chars, astral-plane emoji (2 UTF-16 units), line boundaries, EOF.
- [ ] **P5 — Path ↔ `file://` URI.** Percent-encoding, Windows drive letters (`file:///C:/…`), round-trip guarantees. Canonical path (`Buffer.path`) is the SSOT for outgoing URIs; incoming URIs canonicalize before buffer lookup. Respect the existing UNC-stripping convention for display.
- [ ] **P6 — `ChangeSet` → `TextDocumentContentChangeEvent[]`.** Converter from HUME's retain/insert/delete ops to LSP incremental change ranges, using P4 for coordinates. Lives in `hume-lsp` (needs the C1 scaffold — the one Step 0 item that isn't workspace-independent). Tests: single insert, single delete, multi-op sets, edits spanning line boundaries; oracle = applying the LSP events to a plain string mirror must reproduce the post-edit rope.
- [ ] **P7 — Event-loop timer wheel.** Nearest-deadline registry integrated with P3's wake predicate (`poll` timeout = min(8ms-if-work-pending, nearest deadline)). Rust-side API only here; Steel builtins are B4. Tests: deadline ordering, cancellation, no busy-wheel when idle.
- [ ] **P8 — Boundary-cost spike (measure, then decide).** Benchmark JSON↔SteelVal conversion + Steel-side iteration at 100 / 1 000 / 5 000 items of diagnostic-shaped and completion-shaped data, and per-call Steel dispatch overhead. Output: a short note in this file's decisions/OQ tables fixing the diagnostics-exposure cap and the completion scorer shape. Throwaway benchmark code — not shipped.

## Step 1 — LSP core (Rust data plane)

The `hume-lsp` crate plus the editor-side glue that makes a server real: spawn, handshake, document sync, diagnostics in memory. After this step nothing is visible except `:lsp-status` and the message log — but the data plane is complete.

- [ ] **C1 — Crate scaffold.** `hume-lsp/` workspace member; deps: `lsp-types`, `serde`, `serde_json`, `hume-editing`. No `hume-editor`/`hume-engine` dependency — enforce like `hume-treesitter`.
- [ ] **C2 — JSON-RPC codec.** `Content-Length` framing (read + write), message enum (`Request`/`Response`/`Notification`), request-id allocation and response correlation. Malformed frames fail loudly (log + drop connection), never silently skip bytes.
- [ ] **C3 — Server process management.** Spawn via `std::process::Command` with piped stdio; reader thread (frame → deserialize → mpsc), writer thread (mpsc → serialize → stdin), stderr thread (line-buffered → log channel). `ServerHandle` owns threads + child; kill-on-drop; reader EOF = crash signal.
- [ ] **C4 — `LspBackend` trait + inline double.** Mirror `ParseBackend`/`InlineParseBackend`: trait with `send_*`/`drain`/`has_pending`, boxed on the editor; a synchronous in-process double that answers scripted responses for deterministic tests — no child process, no threads. The double must also serve Steel-side tests of `core:lsp` (Step 4 features are testable against scripted server responses).
- [ ] **C5 — Lifecycle.** `initialize` (advertise client capabilities incl. `positionEncoding: ["utf-8", "utf-16"]`, incremental sync) → store negotiated `ServerCapabilities` → `initialized`. Graceful `shutdown`/`exit` on editor quit and `:lsp-stop`. Crash detection via reader EOF → status message; restart manual (`:lsp-restart`) pending the open question. Capabilities are Steel-readable (B3) — sync behavior they drive stays Rust.
- [ ] **C6 — Request bookkeeping.** Pending-request map with deadlines checked at drain time (no timer thread); in-flight requests count as pending work for P3's wake predicate, so drains — and deadline checks — run at poll cadence instead of waiting for the next input event. Timed-out requests logged and dropped. `$/cancelRequest` sent when the editor loses interest. Responses tagged at request time with the `text_gen` of the buffer named in the params' `textDocument` URI (requests without one are exempt from staleness); stale responses discarded at drain by default (parse-worker staleness discipline) — Steel callbacks can opt in to receiving stale results where harmless (e.g. hover). Timeout values and cancel policy are Steel-tunable knobs.
- [ ] **C7 — Document sync glue (hume-editor).** On buffer open with a matching server: `didOpen` (full text, `languageId` = `Buffer.language`, version = `text_gen`). Every mutation: incremental `didChange` built from the returned `ChangeSet` via P6 (undo/redo included — they return ChangeSets too). `didSave` on write, `didClose` on `:bd`. Version is always `text_gen` — no second counter. Pure protocol, zero customization value: never touches Steel.
- [ ] **C8 — Server registration.** `LspServerConfig { command, args, root_markers, init_options, settings }` in a side-table keyed by language name in `hume-editor` (the `cmd_owners` pattern) — not a field on `LanguageConfig`, which lives in `hume-treesitter` and shouldn't carry LSP concepts. New init-only Steel builtin `register-lsp-server!` following the `%define-language!` / `PendingLanguageReg` queueing pattern (`hume-scripting/src/builtins/syntax.rs`). Workspace root: walk up from the file's directory to the first `root_markers` hit; fall back to cwd. Server identity is (language, workspace root): the first buffer open whose pair has no running server spawns it (C3) and runs the C5 handshake; later buffers with the same pair attach to the running instance.
- [ ] **C9 — Diagnostics store (Rust-ingested).** `publishDiagnostics` → per-buffer store keyed `(server, buffer)`, coalesced at drain (only the latest notification per file survives a frame), positions converted via P4 at ingest, ranges remapped through subsequent edits via the P2 batch cursor. **Bulk never reaches Steel**: Steel gets the `on-diagnostics-changed` signal, per-buffer severity counts, and bounded pull-builtins (B5) — cap calibrated by P8. Display policy (severity filter, which decorations enabled, formats) is Steel-owned via knobs, not per-message processing.
- [ ] **C10 — Observability + lifecycle commands.** `:lsp-status` typed command (servers, state, pending counts, root); `:lsp-stop` / `:lsp-restart` typed commands driving the C5 lifecycle; server stderr → message log with server-name prefix.

## Step 2 — Steel platform

The bridge and primitives that make Steel the feature layer. This step is the heart of the community-offload goal: after it, a plugin can reach any LSP method and any editor surface.

- [ ] **B1 — JSON↔SteelVal codec.** `serde_json::Value ↔ SteelVal` both directions (objects ↔ hashmaps, arrays ↔ lists, null ↔ void — `#f` would collide with JSON `false` on round-trip). Foundation for everything below. Sized by the P8 spike; conversion happens at drain time, off the render path.
- [ ] **B2 — Generic LSP bridge.** `(lsp-request server method params callback)` → id-tagged request; callback stored Rust-side, invoked at drain through the existing hook-queue delivery with the decoded response. `(lsp-notify server method params)` fire-and-forget. `(on-lsp-notification method handler)` for server-initiated notifications not consumed by the core (C9 claims `publishDiagnostics`; everything else flows to Steel). Requests auto-tagged with `text_gen`; stale-drop by default, opt-out flag per request (C6). Errors surface as an error argument to the callback — no silent drops.
- [ ] **B3 — Introspection builtins.** `(lsp-capabilities server)` (decoded `ServerCapabilities`), `(lsp-server-status)`, `(buffer-generation bid)` for Steel-side staleness checks, `(lsp-server-for-buffer bid)`.
- [ ] **B4 — Steel timers.** `(after ms thunk)` on the P7 wheel; `(debounce ms thunk)` returning a callable that coalesces bursts. Hook registration variants with built-in debounce (used by B7's viewport hook).
- [ ] **B5 — Decoration stores + setters.** Steel-writable stores rendered by Rust providers (Step 3): `(set-inlay-hints! bid hints)`, `(set-signs! source bid signs)`, `(set-virtual-lines! source bid lines)`, `(set-extra-highlights! source bid spans)`. Plus the C9 diagnostics pull side: `(diagnostics-for-buffer bid #:severity s #:range r)` bounded per P8, `(diagnostic-counts bid)`. Store writes are cheap (swap a Vec behind the existing Arc/RwLock provider pattern); positions in stores are remapped through edits via P2 like diagnostics.
- [ ] **B6 — Edit + navigation primitives.** `(apply-text-edits! bid edits)` → one ChangeSet transaction, one undo step, version-checked. `(apply-workspace-edit! wsedit)` → the Rust multi-file engine (per-file transactions, versioned-document checks, unopened-file policy per open question). `(goto-location! loc)` → open buffer if needed + jump with jump-list push (after-commit-point discipline). These are correctness-critical shared machinery — one Rust implementation, every feature and plugin composes it.
- [ ] **B7 — New hooks.** `on-lsp-attach` (server ready for buffer), `on-diagnostics-changed` (signal only — pull via B5), `on-viewport-change` (debounced via B4 — new hook, fires on scroll/resize), insert-mode trigger-character hook (fires when typed char ∈ a registered set; serves completion trigger chars and signature help). All through the existing `fire_hook_silent`/`drain_hooks` path.
- [ ] **B8 — Completion orchestration API.** Completion items live in a Rust store with a Rust prefix/fuzzy filter (per-keystroke over 1k items — data plane). Steel drives the session: `(completion-begin! bid items #:incomplete f)`, `(completion-update-filter! text)`, `(completion-top n)`, `(completion-accept! idx)` (applies the item's textEdit via B6), `(completion-dismiss!)`. `completion-begin!`'s `items` arrive via the B2 callback — the full list crosses the boundary once at ingest (per user intent, the guardrail's calibrated exception); every per-keystroke path after that stays in Rust. If P8 rules the crossing out at 1k items, the raw-response-to-store routing flag from the guardrail decision replaces it. Optional Steel scorer hook — shape (all-candidates vs re-rank-top-N) decided by P8.

## Step 3 — UI surfaces

Generic, Steel-scriptable widgets plus store-fed render wiring. The engine primitives mostly exist (reserved `HighlightTier::Diagnostic`, `SignColumn`/`SignSource`, `VirtualLineSource`, `InlineDecoration`, `OverlayProvider`) — LSP is their first client, not their owner.

- [ ] **U1 — Diagnostic underlines.** Third `SharedHighlighter` at `HighlightTier::Diagnostic` registered in `build_pane` (`hume-editor/src/ui/mod.rs`), fed per-frame from the C9 store (visible lines only), styled by severity scopes (`diagnostic.error`, `diagnostic.warning`, …). Plain underline until ratatui grows underline-shape support (ROADMAP open question: undercurl). B5's generic `set-extra-highlights!` store is wired here too, as its own `SharedHighlighter` registration (tier per open question). Steel knobs: severity floor, enable/disable.
- [ ] **U2 — Diagnostic gutter signs.** `SignSource` over the C9 store; first real `SignColumn` registration. Also the first consumer for `ProviderSet::remove` (ROADMAP open question: unwired) if a `:set` toggle is included. B5's generic `set-signs!` store rides the same `SignColumn` — plugin signs and diagnostic signs merge by the existing priority rules.
- [ ] **U3 — Statusline diagnostics element.** Error/warning counts for the focused buffer via `(diagnostic-counts)`; new statusline element following the existing element registry. Decide `$/progress` spinner here (open question).
- [ ] **U4 — Cursor-anchored popup widget.** New `OverlayProvider` positioned at a buffer cursor with flip/clamp at viewport edges. Steel-scriptable: `(show-popup! text #:anchor cursor)`, `(close-popup!)`. The existing `CompletionOverlay` is statusline-anchored — geometry not reusable, cell-painting approach is. Serves hover, signature help, and the completion menu.
- [ ] **U5 — Selection menu widget.** Popup variant with a selectable item list + Steel on-select callback: `(show-menu! items on-select)`. Serves code actions; shares U4's geometry engine.
- [ ] **U6 — Class B bottom drawer (minimal) + location list.** The M12 drawer scoped to what LSP needs: full-width, auto-sized (≤ ~50% height), read-only, scrollable. Built-in location-list mode: `(show-drawer-list! items on-select)` with `(file, line, col, text)` rows and keyboard nav (next/prev/Enter-to-jump via B6's `goto-location!`). Serves references, multi-result goto, `:diagnostics`, hover overflow. Full drawer polish stays M12.
- [ ] **U7 — In-buffer completion menu + dispatch.** Insert-mode completion flow: manual trigger (e.g. `Ctrl+Space`) + B7 trigger-char hook; menu rendered via U4 at the cursor showing B8's top-N; selection state reusing `CompletionState` where it fits. Minibuffer completion path untouched.
- [ ] **U8 — Inline diagnostics (`VirtualLineSource`).** First real implementor: virtual lines under diagnostic lines, text from B5's store (Steel formats the *visible* diagnostics on change, bounded + cached — never per frame). **Triggers the deferred editor rewiring** from ROADMAP decision "Virtual-line-aware scroll/cursor math scope": thread `&ProviderSet` through `cursor::screen_pos`/`screen_to_char_offset` and `scroll::ensure_cursor_visible`/`scroll_cursor_to_row`/`scroll_backward_from_cursor` (~10 interlinked, heavily-tested functions — budget as its own sizable sub-task).
- [ ] **U9 — Inlay-hint rendering.** `InlineDecoration` impl over B5's inlay-hint store, registered in `build_pane`; the pipeline already collects `decorations_for_line` per line (`pane_render.rs`) — store + registration only. F10 renders through this with zero Rust changes.

## Step 4 — Features (Steel, `core:lsp`)

Each feature is Steel code composing Steps 2–3 primitives; each lists what it composes. All are testable against the C4 inline double with scripted responses. Rust changes in this step should be zero — if a feature needs one, that's a missing platform primitive (fix the platform, not the feature).

- [ ] **F1 — Hover.** Normal-mode keybinding → `lsp-request textDocument/hover` → `show-popup!` (markdown as plain text v1); overflow to drawer per open question. *(B2, U4, U6)*
- [ ] **F2 — Goto definition family.** `definition` / `declaration` / `typeDefinition` / `implementation` → single result: `goto-location!`; multiple: `show-drawer-list!`. *(B2, B6, U6)*
- [ ] **F3 — Completions.** Trigger via U7 → `lsp-request textDocument/completion` → `completion-begin!`; incremental filtering via `completion-update-filter!` (no re-request unless `isIncomplete`); `completionItem/resolve` on selection; accept via `completion-accept!`. Plain-text insertion v1. Stale requests auto-cancelled (C6). *(B2, B8, U7)*
- [ ] **F4 — Diagnostics navigation.** Next/prev diagnostic via `diagnostics-for-buffer` + `goto-location!`; `:diagnostics` opens the drawer list. Default keys go under the `g` goto prefix (e.g. `gn`/`gp`, both free) — **not** `]d`/`[d`: `]`/`[` are Normal-mode leaves for paste-ring cycling (`keymap/defaults.rs`) and binding a sequence there would silently replace them. Exact keys chosen at F11. *(B5, B6, U6)*
- [ ] **F5 — Rename.** Minibuffer prompt (prefilled with symbol under cursor) → `lsp-request textDocument/rename` → `apply-workspace-edit!`. *(B2, B6)*
- [ ] **F6 — References.** `textDocument/references` → `show-drawer-list!`. *(B2, U6)*
- [ ] **F7 — Signature help.** B7 trigger-char hook (debounced) → `lsp-request textDocument/signatureHelp` → `show-popup!` with active-parameter highlight; dismiss on `)` / mode exit. *(B2, B4, B7, U4)*
- [ ] **F8 — Formatting.** `:fmt` → `textDocument/formatting` (range variant when a selection spans at least one full line; sub-line selections format the whole buffer — HUME selections are never empty, so bare "on selection" would always match) → `apply-text-edits!` (one undo step). Never format-on-save by default; ships as a commented hook recipe. *(B2, B6)*
- [ ] **F9 — Code actions.** Keybinding → `textDocument/codeAction` for selection/cursor → `show-menu!` → `apply-workspace-edit!` or `workspace/executeCommand` via `lsp-request`. *(B2, B6, U5)*
